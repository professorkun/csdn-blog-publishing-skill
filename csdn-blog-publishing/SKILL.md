# 技术博客写作与多平台发布

将真实排障或开发经验写成可以公开阅读的文章，并把它送到 CSDN 与 GitHub，每一步都留下可核验证据。重点保留可复用的解决过程，不把私人环境变成文章的一部分。

三个原则：**脱敏在前、用户确认在外部写入之前、匿名回读在最后**。任何一步失败都如实报告状态，不用推测代替回执。

## 写作与脱敏

- 先区分已验证的事实、推断和待长期观察项；问题背景简短，重点说明判断、处理和验证。
- 不展示私人 Wiki 的真实路径、目录、文件名、页面内容、任务 ID 或任务正文。
- 不展示 NAS 的真实主机名、内网地址、端口、账号、域名、日志、备份位置、服务配置或任何凭据。
- 示例代码使用通用文件名、模拟数据和替代任务文本，并在文章中注明“脱敏示例”。不要复制生产脚本、原始日志或配置片段。
- 使用自然、通俗的中文。代码按“目的 → 最小片段 → 说明或预期输出”分步展示，而不是整段粘贴完整脚本。
- 日常草稿阶段只快速检查明显的账号、凭据、内网地址、真实路径、私人截图和未经验证的结论；未准备提交时，不要求完成公开页验收或 Skill 副本校验。

## 草稿工作流

1. 根据可追溯证据起草标题和正文；对代码、输出、图片和标题逐项做脱敏检查。
2. 写入 CSDN 编辑器前，确认当前文章内容已被用户认可；编辑器自动保存只能描述为“草稿已自动保存”。
3. 准备提交审核、发布或修改已公开文章时，复核标题、正文、代码渲染、输出示例、图片、分类、标签、可见范围和引用链接；检查正文、代码、命令、日志、截图、外链和可见附件中没有凭据、个人隐私、内网地址、真实 NAS/Wiki 路径或未授权内部信息。
4. 推断和未验证内容必须明确标注。对截图、图片和附件先检查可见内容；来源文件包含个人或内部信息时，再按需检查文件名、元数据和嵌入信息。无法检查时，标记为“未完成检查”，不得声称已完成脱敏。
5. 发现疑似敏感信息、事实状态不明或权限不清时，必须停止后续提交动作，标记为“待脱敏修订”或“待核验”，并向用户报告阻断原因；不得继续执行外部写入。

## 发布状态与证据

按下列状态记录文章进度；后一状态不能由前一状态推断。

1. `草稿/自动保存`：本地文件或编辑器内容可见。
2. `已准备提交`：发布前检查已完成，尚未发生外部提交。
3. `已提交审核`：平台已接收投稿，有提交结果、文章 ID 或后台记录。
4. `后台显示已发布`：内容管理页显示文章已发布。
5. `公开页已验证`：公开 URL 可访问，且完成最小渲染检查。

“后台显示已发布”不等于“公开页已验证”。公开页受登录、缓存、地区或平台权限影响而无法核对时，记录为“公开页待验证”；不要据此断定发布失败或公开效果已验证。

## 发布边界

- 点击“提交审核”或“发布”、修改已公开文章及外部同步都是外部写入。每一篇文章都必须在即将执行前取得用户针对当前草稿的明确确认；检查通过、过往授权或“继续写”不等于本次外部写入授权。
- 发布后至少核对公开 URL 可访问、标题与正文完整、代码块正常渲染、图片可加载、外链可打开且不指向内部环境、分类/标签/可见范围正确；记录公开链接、文章 ID、核验时间和未验证项。截图只在异常、争议或用户明确要求时保存。
- 无法完成公开页核对时，只报告对应的已知状态和“公开页待验证”，不要宣称已公开生效。

## 平台执行（CSDN + GitHub）

写作与脱敏完成后，按下述顺序执行；具体命令模板见 `scripts/`。

### 前置检查

| 项 | 要求 | 不可用时 |
|---|---|---|
| 用户确认 | 对**当前这篇草稿**的明确发布确认 | 停在"已准备发布"，不做任何平台写入 |
| 脱敏 | 已完成，且用关键词扫描复检 | 标"待脱敏修订"并阻断 |
| Chrome | 独立配置目录可启动 | 让用户本人登录，不索取密码 |
| GitHub 凭据 | `git credential fill` 能返回账号（不回显 token） | 改由用户提供或手动建仓 |

脱敏复检建议扫描：内网地址、真实主机名、绝对路径、账号标识、渠道 ID、框架专名。中文正文里像 `HEARTBEAT_OK` 这类实现常量应替换为通用占位符。

### 启动浏览器（CSDN 侧）

```
"<CHROME_EXE>" \
  --remote-debugging-port=9222 \
  --user-data-dir="<ISOLATED_PROFILE_DIR>" \
  --no-first-run --no-default-browser-check \
  "https://mp.csdn.net/mp_blog/creation/editor"
```

确认 `GET http://127.0.0.1:9222/json/version` 可用。不读取密码、Cookie 或凭据；发布结束**关闭该浏览器实例**，不留监听端口。

### 写入编辑器

编辑器是 CKEditor（正文在 `iframe.cke_wysiwyg_frame` 内），不是 CodeMirror：

1. **标题**：`textarea.el_mcm-textarea__inner`，用原生 setter 赋值后派发 `input`/`change`，否则框架不认。
2. **正文**：`switchmarkdown` 工具栏按钮实测点击无效、也取不到对应命令，**不要依赖它**。把 Markdown 转成 HTML 后调用 `CKEDITOR.instances[…].setData(html)`。
3. **标签**：先点 `button.tag__btn-tag.active` 打开选择器，向占位符含"键入可添加"的 `input` 输入关键词，再**点击**候选项（回车无效）；等级不足三级只能用平台已有标签。
4. **发布设置**：核对文章类型、创作声明、可见范围、模板、备份开关。

两个必踩的坑：

- **编码**：base64 传给页面时 `atob()` 得到字节串，中文会变成 `&aring;&copy;…` 实体；必须再 `TextDecoder('utf-8').decode(bytes)`。判据是 `getData().length` 异常膨胀。
- **换行**：走 Markdown/Cledit 模式时 `Input.insertText` 不保留换行，需要真实 `Ctrl+V`；走 `setData()` 路线则不存在该问题。

写入后回读 `title`、`dataLen`、`<h2>`/`<pre>`/`<table>` 数与源文件对照。

### 发布与回读

点击文本为"发布博客"的按钮，轮询跳转：成功页形如 `mp.csdn.net/mp_blog/creation/success/<ARTICLE_ID>`。随后打开公开页回读标题、代码块与表格数。**平台会把正文 `##` 归一为页面内更低层级标题**，按页面实际层级统计。最后做一次匿名请求确认 HTTP 200，把"登录态可见"与"公开可见"分开记录。

### GitHub 镜像

- SSH 先自测（`ssh -T git@github.com`）；常见 `Permission denied (publickey)` 说明密钥未绑到目标账号。此时用 Windows 凭据管理器里的 HTTPS 凭据：`"protocol=https`nhost=github.com`n`n" | git credential fill`，只打印 token 长度与前缀，不打印明文。
- 用 `POST /user/repos` 建公开仓库，`description` 写文章摘要，`homepage` 指向 CSDN 原文。
- README 由**同一份发布正文**生成：去 front matter、去正文自带 H1 与重复引用块、截断"关联记录"及其后内容，头部补原文链接与脱敏声明；生成后复检不得残留内部链接语法或私有路径。
- 推送后用 API/raw 匿名核验 `private`、`default_branch`、README 字节数。**PowerShell 会把 git 进度输出当错误**，以回读为准，不要凭 exit code 判断失败。

## 平台执行的状态与证据

沿用下文五级状态，并额外记录：文章 ID 与公开 URL、匿名访问状态码与字节数、仓库与提交哈希、README 字节数与泄漏扫描结果、以及未验证项（审核结果、页面渲染、图片加载）。

## 文章配图（可选）

- 配图不是文章完成的必需项。只有图片能明显帮助理解抽象概念、使用场景或文章结构时才生成；文字、代码、Mermaid、SVG 或真实截图已经足够清楚时，不额外生成。图片数量根据文案的信息密度、概念转换、阅读节奏和每张图带来的明确理解收益决定，不设固定上限；每张图都必须服务于具体的解释或导航需求，不得为增加视觉密度插入重复或无新信息的图片。
- 可使用封面/主题引导图、概念解释插图、少量非精确信息图或长文章节过渡图。图片放在摘要后、概念首次解释后或对应章节附近，并配简短图注；技术示意图标注“示意图；具体实现以正文代码或实测为准”。
- 不使用 ImageGen 生成代码、命令、日志、SQL、表结构、精确架构图、端口/字段/版本号、真实性能图表、测试结果或平台状态。它们应使用代码、Mermaid、SVG、确定性图表或真实截图。
- 普通新图默认使用内置 `image_gen`；不主动切换 CLI。提示词、参考图和输出图不得含 Token、Cookie、账号、真实路径、内网地址、私人截图、未脱敏日志或未验证结论。使用用户提供图片前，确认用户有权使用且已完成脱敏。
- 生成图中的文字、节点、箭头、数字、设备、品牌和界面默认不具备事实效力，必须人工逐项核对。无法保证准确时，要求生成无文字概念图，并把准确说明放在正文、图注或确定性图表中；生成图不得用于证明性能、兼容性、部署状态或测试结果。
- 生成后检查隐私、构图、文字、技术误导、品牌/人物/界面、水印和禁止项。只将最终选定图片复制到本篇文章现有或经确认的资产目录，使用不覆盖的版本化文件名；未选中的变体不进入文章资产目录。
- 生成或本地插入图片不构成 CSDN 提交、发布、修改公开文章或外部同步授权。发布后按现有公开页验收规则额外检查图片加载、尺寸比例、图注和排版；图片异常或公开页无法访问时，不得标记为“公开页已验证”。

## 归档与证据

把每次发布的原始证据（公开链接、文章 ID、提交哈希、字节数、核验方式）记到使用者自己的记录系统中。本 Skill 不规定归档位置，也不假定任何私有目录结构。

归档只在用户要求时进行；写入前后核对目标文件哈希。出现冲突、错误或哈希不一致时报告"待核验"，不得声称已更新。

## 附：可复用脚本

`scripts/` 下是平台执行的最小实现，占位符替换后可直接跑：

- `cdp.mjs`：极简 CDP 客户端（`tabs` / `nav` / `eval` / `click` / `shot`，端口用 `CDP_PORT` 覆盖）。
- `md2html.mjs`：Markdown → HTML，默认截断"关联记录"不发布。
- `mk-readme.mjs`：由发布正文生成 GitHub README，含泄漏复检。
- `fill-csdn.mjs`：写标题与正文并回读校验。
- `publish-csdn.mjs`：点发布并轮询成功页、提取文章 ID。
- `gh-create-repo.mjs`：用 token 创建公开仓库（幂等）。
- `tag.mjs` / `clicktag.mjs` / `cleartag.mjs`：标签选择器的输入、点击候选与清空输入。

## Skill 副本维护

本机安装版、Wiki 归档版和公开仓库版用途不同。仅在修改或同步 Skill 时，先确认目标副本和基线哈希，修改后重新计算哈希并核对副本一致性。无法读取副本、无法计算哈希或哈希不一致时，记录为“副本未同步/未完成检查”；哈希一致只说明文件内容一致，不代表 Skill 已安装、已加载或已生效。
